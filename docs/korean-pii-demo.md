# 한국어 개인정보 마스킹 데모 (Korean PII masking demo)

[English](korean-pii-demo.en.md) | **한국어**

상담 로그를 조회하면 응답 본문에 고객의 휴대전화·주민등록번호·계좌번호가 함께 실려 옵니다. 조회 자체는 정당한 업무이므로 막을 일이 아니고, **응답에서 개인정보만 지운 뒤 전달**하는 것이 맞습니다(위협 T-02·T-08, `mask_then_allow`). 이 데모는 그 차이를 같은 요청을 두 번 보내서 보여 줍니다.

## 무엇을 비교하나

| | 미적용 | 적용 |
| --- | --- | --- |
| 호출 대상 | 도구 서버 직접 | 게이트웨이 경유 |
| 판정 | 없음 | `mask_then_allow` |
| 응답 본문 | `010-3456-7890`, `881124-2300149`, `계좌번호: 110-234-567890` | `[PHONE]`, `[RRN_LIKE]`, `[BANK_ACCOUNT]` |

**에이전트 코드는 양쪽이 동일합니다.** 바뀌는 것은 엔드포인트 하나뿐입니다.

## 재현

데모 프로파일이 떠 있어야 합니다.

```bash
docker compose --profile demo up -d
```

```bash
./scripts/demo-korean-pii.sh
```

스크립트는 결과를 출력만 하지 않고 **검증**합니다. 미적용 응답에 세 값이 그대로 있는지, 적용 응답에는 하나도 남지 않고 태그로 바뀌었는지, 판정이 `mask_then_allow`인지를 확인하고 하나라도 어긋나면 0이 아닌 코드로 끝납니다.

Agent 관점으로 보려면 demo-agent를 호출합니다.

```bash
curl --fail --silent --request POST http://localhost:3002/demo/consultation-log
```

응답의 `guarded.text`는 마스킹된 본문, `vulnerable.text`는 마스킹되지 않은 본문이고, `maskedTypes`가 종류별 마스킹 건수입니다. 적용 경로만 필요하면 `?compare=false`를 붙입니다.

## 데이터

`TCK-2026-9001` 상담 로그 한 건을 사용합니다. 나머지 시드 티켓은 종류별 재현율을 측정할 수 있도록 **개인정보를 한 종류씩만** 담지만, 이 티켓만은 휴대전화·주민등록번호·계좌번호를 한 본문에 함께 넣었습니다. 세 종류가 한 응답에서 동시에 마스킹되는 것을 보여야 하기 때문입니다.

모든 값은 합성입니다. 주민등록번호와 계좌번호는 탐지기가 검증하는 체크섬 형식만 만족시킬 뿐 실제 사람이나 계좌와 무관하며, 시드는 [`generate-tickets.ts`](../apps/demo-mcp-tools/scripts/generate-tickets.ts)가 결정론적으로 생성합니다. 시드를 바꿨다면 다시 생성해 커밋하세요.

```bash
npm run seed:tickets --workspace @guardmcp/demo-mcp-tools
```

## 마스킹 전후를 비교하는 근거

게이트웨이는 마스킹 **전** 원문을 보관하지 않습니다. 남기는 것은 다이제스트 참조뿐이고(NFR-04, [`maskDiff.ts`](../packages/gateway/src/pipeline/maskDiff.ts)), 원문 보관은 운영자가 환경변수로 명시적으로 켤 때만 동작합니다.

따라서 "전" 쪽은 게이트웨이에서 꺼내 오는 것이 아니라 **게이트웨이를 거치지 않고 한 번 더 실행해서** 얻습니다. 번거로워 보이지만 이게 정확한 설계입니다 — 비교를 위해 원문을 어딘가 쌓아 두면, 유출을 막으려고 만든 시스템이 유출 대상을 하나 더 만드는 셈이 됩니다.

## 현재 한계

Detector Console(SCR-401)에서 같은 비교를 보려면 Control Plane의 `/detect/preview`가 실제 탐지기를 거쳐야 합니다. 현재 그 엔드포인트는 전화번호·이메일·민감 경로 세 가지 정규식만 자체적으로 들고 있어 **주민등록번호와 계좌번호를 탐지하지 못하고**, 마스킹 표기도 `[PHONE]`이 아니라 `010-****-5678` 형태입니다. Control Plane에서 게이트웨이로 나가는 클라이언트가 아직 없어 이 연결은 Control Plane API 작업(GMCP-80)에 속합니다. 그 전까지 콘솔 화면의 개인정보 미리보기는 목 데이터로 동작합니다.
