# 선택적 LLM 2차 판별기

[English](llm-adjudicator.en.md) | **한국어**

규칙 기반 탐지가 확실하지 않은 **경계 구간에만** 소형 LLM에게 두 번째 의견을 묻는 옵트인 플러그인입니다(FR-INJ-04). **기본은 꺼져 있습니다.**

## 왜 기본이 꺼져 있나

켜는 순간 **검사 대상 텍스트가 외부 모델로 나갑니다.** 그래서 이건 탐지 성능 결정이기 이전에 **정보 공개 결정**입니다. 운영자가 어디로 무엇이 나가는지 알고 켜야 하므로, 기본값은 꺼짐이고 어댑터도 기본 제공하지 않습니다.

의존성 격리도 같은 이유입니다. 켜지 않으면 어댑터가 생성되지 않고, 게이트웨이 모듈 그래프 어디에도 LLM 제공자 SDK가 들어오지 않습니다. **"하드 의존 없음"은 설정이 아니라 구조로 보장됩니다.**

## 어떻게 켜나

두 가지를 모두 해야 합니다. 하나만으로는 아무 일도 일어나지 않습니다.

```bash
export LLM_ADJUDICATOR_ENABLED=true
```

그리고 부팅 코드에서 어댑터를 등록합니다.

```ts
import { registerLlmAdapter } from "@guardmcp/gateway/llm/adapter.js";

registerLlmAdapter({
  name: "gemma-3-4b",              // 이벤트에 남는 이름. 키나 엔드포인트를 넣지 마세요
  async classify({ text, ruleRiskScore, signal }) {
    // 여기서 본인의 모델을 호출합니다. signal 을 반드시 전달하세요.
    return { label: "injection", confidence: 0.9 };
  },
});
```

어댑터를 기본으로 하나 넣어두지 않은 것은 의도한 것입니다. 넣으면 특정 벤더가 암묵적 정답이 되고, 이 간접층이 존재하는 이유가 사라집니다.

## 언제 호출되나

| 위험 점수 | 동작 |
| --- | --- |
| 0–39 | 호출 안 함 — 규칙이 아무것도 못 찾음 |
| **40–69** | **호출** — 경계 구간 |
| 70+ | 호출 안 함 — 파이프라인이 이미 승인 대기 이상으로 올림 |

70 이상에서 묻지 않는 이유는, **어차피 내려질 판정을 확인받느라 지연과 정보 공개를 지불하기 때문**입니다. 구간은 `packages/gateway/src/rules/llm-adjudicator.json`에서 바꿀 수 있습니다.

## 올릴 수는 있고, 내릴 수는 없습니다

이게 이 기능의 가장 중요한 성질입니다.

- 모델이 확신을 갖고 `injection`이라 답하면 판정을 **`require_approval`로 올립니다**
- 모델이 `benign`이나 `unsure`라 답하면 **규칙 판정이 그대로 유지됩니다**

내릴 수 없게 한 이유는, 틀린 답 하나가 — 또는 침해된 어댑터가 — 게이트웨이가 이미 내린 차단을 설득해 풀 수 있으면 안 되기 때문입니다. 모델은 **경계 사례를 사람 앞에 놓는 근거**이지, 그 사례를 대신 판단하는 주체가 아닙니다.

확신 임계값은 `minConfidence`(기본 0.7)입니다. 그보다 낮은 인젝션 주장은 기록되지만 올리지 않습니다.

## 실패하면 어떻게 되나

어댑터가 타임아웃·예외·형식 오류를 내면 **규칙 판정이 그대로 유지되고 요청은 계속됩니다.** 기록은 남습니다.

```json
{ "model": "gemma-3-4b", "label": "unsure", "confidence": 0,
  "latencyMs": 801, "escalated": false, "failure": "timeout" }
```

같이 죽을 수 있는 2차 의견은 선택 사항이 아닙니다. 기본 예산은 800ms이고 `timeoutMs`로 조정합니다.

## 지연은 따로 기록됩니다

`latencyMs`는 규칙 파이프라인 타이밍에 **합산되지 않습니다.** NFR-01의 지연 예산은 규칙에 대한 주장이고, 남의 모델로 나가는 네트워크 호출이 그 안에 숨으면 그 주장이 무의미해집니다. GuardEvent의 `llmAdjudication`에 별도 필드로 실립니다.

## 남은 것

- 도구 설명 검사(`tools/list` 격리 경로)는 동기 함수라 판별기를 태우지 않습니다. 별개 표면이고 이 티켓 범위가 아닙니다.
- 비용 집계는 없습니다. 어댑터가 호출당 비용을 아는 유일한 주체라, 필요하면 어댑터 쪽에서 계측하는 것이 맞습니다.
