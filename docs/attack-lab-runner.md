# Attack Lab 러너 (Attack Scenario Runner)

[English](attack-lab-runner.en.md) | **한국어**

[공격 시나리오 카탈로그](attack-scenarios.md)는 시나리오마다 **기대 차단 지점**을 적습니다 — 이 탐지가, 이 방향과 서버 신뢰 등급에서, 이 정책에 닿아 이 판정으로 끝난다. 러너는 그 주장을 실제로 실행해서 확인합니다(FR-LAB-01).

```bash
npm run attacklab
```

## 벤치마크와 무엇이 다른가

| | `npm run bench` | `npm run attacklab` |
| --- | --- | --- |
| 묻는 것 | 탐지기가 뭔가 봤는가 | **정책이 어떤 판정을 냈는가** |
| 파이프라인 | ③ 탐지 | ③ 탐지 → ⑤ 위험 점수 → ⑥ 정책 판정 |
| 결과 단위 | 집계 수치(recall, 차단율) | **시나리오 이름별 판정** |

벤치마크의 차단율이 떨어지면 어떤 규칙이 깨졌는지 따로 찾아야 합니다. 러너는 `A-13 FAIL expected block, got warn` 처럼 이름과 함께 나옵니다.

러너는 `detect`·`scoreRisk`·`decide`를 **그대로 호출합니다.** 복사한 구현이 아니라 실제 모듈이라, 통과가 배포되는 파이프라인에 대한 진술이 됩니다. 게이트웨이의 HTTP 표면은 일부러 쓰지 않습니다 — 시나리오는 아무것도 안 띄운 CI에서도 재현되어야 합니다.

## 판정 등급

| 등급 | 뜻 | CI |
| --- | --- | --- |
| `PASS` | 파이프라인이 카탈로그가 주장한 차단 지점에 닿았다 | 통과 |
| `FAIL` | 주장한 차단 지점이 성립하지 않았다 | **실패** |
| `GAP` | 카탈로그가 담당 정책을 `null`로 적었고, 목표 판정이 나오지 않았다 | 통과(보고됨) |
| `SKIP` | `automation.mode: "manual"` — 아직 프로브로 재현 불가 | 통과(보고됨) |
| `RUN` | 미적용 모드 — 채점 대상이 아니다 | — |

`GAP`을 실패로 세지 않는 이유는, 만들어진 적 없는 것 때문에 CI가 빨개지면 아무도 그 빨간불을 신뢰하지 않기 때문입니다. 반대로 통과로 세면 없는 보호를 있다고 세는 것이라 더 나쁩니다. **둘 다 아니라서 별도 등급입니다** — 매 실행마다 목록으로 출력됩니다.

## 현재 GAP — 응답 방향 Secret 마스킹이 없습니다

`A-04`·`A-05`·`A-16`~`A-19` 여섯 건이 GAP입니다. 원인은 하나입니다.

응답 방향 정책은 지금 **INJECTION(차단)과 PII(마스킹)뿐**입니다. `SECRET`을 응답에서 마스킹하는 정책이 없어서, GitHub 토큰·AWS 키·개인키·토스 시크릿 키가 도구 응답에 실려 오면 `allow`로 Agent에 그대로 전달됩니다. 탐지는 됩니다 — 판정이 없습니다.

러너가 첫 실행에서 찾아낸 것이고, GMCP-113으로 분리했습니다. 정책이 들어오면 이 여섯 건은 `GAP`에서 `PASS`로 바뀝니다.

## 미적용 모드

```bash
npm run attacklab -- --mode vulnerable
```

검사를 **하지 않습니다.** 판정을 `allow`로 꾸미는 게 아니라 탐지 자체를 돌리지 않습니다 — 게이트웨이가 경로에 없을 때 Agent에 무엇이 도달하는지가 이 모드의 요점이고, 실제 평가에서 나온 `allow`로 흉내내면 전혀 다른 주장이 됩니다.

이 모드는 채점하지 않습니다. 볼 숫자는 "몇 건이 통과했는가"입니다.

## 시나리오 골라 실행

```bash
# 시나리오 ID
npm run attacklab -- --only A-13
# 위협 ID (해당 위협의 모든 시나리오)
npm run attacklab -- --only T-01,T-07
```

## 결과 파일

`reports/attacklab.json`에 기록됩니다. 시나리오마다 프로브별 **단계 이벤트**가 담기고, 각 이벤트는 §8.4 GuardEvent 형태를 따릅니다.

| 필드 | 내용 |
| --- | --- |
| `argsDigest` | 검사한 텍스트의 다이제스트. **원문은 담기지 않습니다**(NFR-04) |
| `verdict` · `riskScore` · `matchedPolicyIds` · `decidingPolicyId` | 판정과 근거 |
| `explanation` | 한국어·영어 판정 사유 |

`explanation`이 모든 단계에 붙는 이유는 Replay가 사유를 되짚어 재구성하지 않게 하려는 것입니다(M3 DoD).

## 다른 진입점

FR-LAB-01은 진입점 셋을 말합니다. 이 문서의 `npm run attacklab`이 그중 하나이고, 나머지 둘은 아직 이 러너에 연결되지 않았습니다.

| 진입점 | 상태 |
| --- | --- |
| `npm run attacklab` | 구현됨 |
| `guardmcp` CLI | GMCP-97 (미구현) |
| `POST /attacklab/run/{scenarioId}` | 요청 접수만 구현됨. 실행은 미연결 — 지금은 `T-01`~`T-08` ID만 받고 카탈로그의 `A-01`~`A-19`는 모릅니다 |

둘 다 `runCatalog()`를 호출하면 되고, 실행 루프를 다시 만들 필요는 없습니다.
