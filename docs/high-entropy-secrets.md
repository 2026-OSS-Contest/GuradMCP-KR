# 고엔트로피 자격증명 안전망 (High-entropy credential safety net)

[English](high-entropy-secrets.en.md) | **한국어**

[Secret 탐지 카탈로그](korean-service-tokens.md)와 `secret.json`은 자격증명을 **모양**으로 알아봅니다. 그건 누군가 이미 그 모양을 적어 둔 경우에만 통합니다. 이 패스는 아무도 적지 않은 것들 — 사내 서비스 토큰, 형식이 바뀐 키, 카탈로그가 들어본 적 없는 벤더 — 을 위한 안전망입니다(FR-SEC-03).

탐지되면 `SECRET.HIGH_ENTROPY`로 보고되고 `[SECRET]`으로 마스킹됩니다.

## 엔트로피만으로는 판정하지 않습니다

이게 이 기능에서 가장 중요한 부분입니다.

**SHA-256 다이제스트, UUID, 커밋 해시, 압축된 번들은 전부 고엔트로피이고 그중 자격증명은 하나도 없습니다.** 엔트로피 임계값만 걸면 빌드 로그의 모든 줄을 신고하게 되고, 그런 탐지기는 곧 꺼집니다. 꺼진 탐지기는 아무것도 못 지킵니다.

자격증명과 다이제스트를 가르는 건 **값이 아닙니다.** 누군가 그 필드를 `checksum`이 아니라 `token`이라고 이름 붙였다는 사실입니다.

그래서 판정이 두 단계입니다.

| 단계 | 무엇을 보나 |
| --- | --- |
| **① 필드 이름** | 자격증명을 소개하는 이름인가 (`api_key`, `token`, `client_secret`, `Authorization` …) |
| **② 엔트로피** | 그 값이 **생성된** 것처럼 보이는가, 사람이 **타이핑한** 것처럼 보이는가 |

①이 후보를 정하고, ②는 그 후보가 진짜 비밀값인지만 거릅니다. 순서가 반대면 안 됩니다.

## 임계값

원천은 [`packages/gateway/src/rules/entropy.json`](../packages/gateway/src/rules/entropy.json)입니다.

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 최소 길이 | 20자 | 짧은 문자열의 섀넌 엔트로피는 잡음입니다 |
| 최대 길이 | 200자 | 그 이상은 자격증명이 아니라 데이터 블록입니다 |
| 임계 (16진수) | 3.6 bits/char | 16개 기호라 최대치가 4.0 근처 — 일반 임계를 걸면 16진 자격증명이 전부 빠져나갑니다 |
| 임계 (그 외) | 4.0 bits/char | base64·영숫자 혼합은 64개 기호를 뽑으므로 더 높은 바를 견딥니다 |
| 신뢰도 | 0.6 | 카탈로그의 모든 규칙보다 낮습니다 |

**신뢰도 0.6인 이유**: 이 패스가 하는 말은 *"이건 자격증명 모양이고 자격증명으로 소개됐다"* 이지 *"이건 GitHub 토큰이다"* 가 아닙니다. 카탈로그 규칙(0.85~0.99)이 훨씬 구체적인 근거를 갖고 있으므로 그보다 낮아야 맞습니다.

## 카탈로그 규칙에 양보합니다

이미 카탈로그 규칙이 잡은 구간은 **보고하지 않습니다.**

```
OPENAI_API_KEY=sk-abcdefghijklmnopqrstuvwxyz1234
                └─ SECRET.LLM_API_KEY 가 이미 담당
```

같은 값을 두 번 세면 위험 점수가 부풀고, 무엇보다 `mask()`가 **겹치는 구간 두 개**를 치환하게 됩니다. 구체적인 규칙이 있으면 그쪽 말이 맞습니다.

## 필드 이름 목록

무엇을 **넣지 않았는지**가 넣은 것만큼 중요합니다.

`hash`, `checksum`, `digest`, `sha`, `commit`, `etag`, `id`, `uuid` — 전부 고엔트로피 값을 담는 이름이고 **자격증명이 아닙니다.** 이걸 목록에 넣는 순간 엔트로피 규칙이 빌드 로그를 신고하기 시작합니다.

필드 이름은 접두사가 붙어도 인식합니다. `INTERNAL_API_KEY`, `legacy_secret_key`처럼요 — 실제 설정 파일에서 자격증명이 가장 흔히 취하는 모양입니다.

## 서비스 추가하기

TypeScript를 고칠 필요가 없습니다. [`entropy.json`](../packages/gateway/src/rules/entropy.json)의 `fields.keywords`에 정규식 조각을 하나 넣으면 됩니다.

새 이름을 넣을 때는 **반드시 음성 샘플도 같이** [`attack-lab/datasets/high-entropy-secrets.json`](../attack-lab/datasets/high-entropy-secrets.json)에 넣으세요. 그 이름을 쓰지만 자격증명이 아닌 문장이 반드시 있습니다.

```bash
npm run test:unit && npm run bench
```

## 측정

`npm run bench`가 리포트의 `highEntropySecrets`에 기록합니다.

| 지표 | 기준 |
| --- | --- |
| `highEntropyRecall` | ≥ 0.90 |
| `highEntropyFpr` | ≤ 0.05 |

**오탐률이 이 기능의 생사를 결정하는 숫자입니다.** 재현율이 조금 낮은 안전망은 여전히 안전망이지만, 오탐이 잦은 안전망은 꺼지고 그러면 0이 됩니다. PII·국내 토큰 지표와 분리해서 재는 이유도 같습니다 — 다른 점수가 좋으면 이 숫자가 나빠진 걸 가릴 수 있으니까요.

## 한계

- **필드 이름이 없으면 못 잡습니다.** 자격증명이 이름 없이 본문에 떠 있으면 이 패스는 후보로도 안 봅니다. 그건 카탈로그 규칙의 몫입니다.
- **사람이 고른 비밀번호는 못 잡습니다.** 엔트로피가 낮아서 통과합니다 — 그건 이 패스가 아니라 정책·운영의 문제입니다.
- 값이 base64로 한 겹 더 감싸여 있으면 놓칩니다. 난독화 해제 패스는 인젝션 규칙만 재검사합니다([난독화 전처리](obfuscation.md)).
